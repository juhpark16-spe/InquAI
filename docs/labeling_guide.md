# 문의 유형·감정 라벨링 기준

학습 데이터, 보충 데이터, 테스트 데이터에 라벨을 붙일 때 이 기준을 따릅니다.
사람마다 답이 다르면 모델도 헷갈리므로, 애매한 문장은 **아래 원칙을 위에서부터 차례로 적용**해 하나로 정합니다.

- 유형 정의: 기획서 2-1 (8개 유형)
- 관련 코드: `backend/training/labels.py`, `backend/training/prepare_data.py`
- 기준이 바뀌면 이 문서를 먼저 고치고, 데이터와 정제 규칙을 맞춘 뒤 다시 학습합니다.

## 1. 8개 유형 요약

| 유형 | 한 줄 정의 | 처리 경로 |
| --- | --- | --- |
| 배송 | 아직 받지 못했거나 막 받은 **첫 배송**에 관한 문의 (일정, 조회, 배송지, 배송비, 오배송·누락·파손) | 조회형 |
| 주문 취소 | **출고 전 주문을 없애는 것**과 그 진행 상황 (취소 후 결제 취소·환불 반영 포함) | 접수형 |
| 교환 | 받은 상품을 **다른 사이즈·색상·새 제품으로 바꾸는 것**과 그 진행 상황 | 접수형 |
| 반품·환불 | 받은 상품을 **돌려보내고 돈을 돌려받는 것**과 그 진행 상황 | 접수형 |
| 결제 | **결제 수단·결제 과정** (결제 오류, 중복 결제, 할부, 입금, 영수증, 카드사 혜택) | FAQ형 |
| 상품 | **상품 자체**에 대한 질문 (재고, 사이즈 추천, 소재, 색상, 사용법, AS, 요청 없는 불량 신고) | FAQ형 |
| 쿠폰·적립금·회원 | **쇼핑몰이 주는 혜택과 계정** (쿠폰, 적립금, 포인트, 등급, 회원가입, 로그인, 회원정보) | FAQ형 |
| 기타 | 위에 속하지 않는 문의 (새 주문 방법, 입점·제휴, 고객센터, 개인정보, 앱 오류, 상품 페이지 표기 오류, 칭찬·불만) | 이관형 |

## 2. 애매할 때 적용하는 원칙 (우선순위 순)

### 원칙 1. 이유가 아니라 **요청**으로 정한다

고객이 원하는 행동이 분명하면 그 행동의 유형입니다. 요청이 없으면 문제의 원인 유형입니다.

| 문장 | 유형 | 이유 |
| --- | --- | --- |
| 사이즈가 커서 작은 사이즈로 교환하고 싶어요. | 교환 | 요청이 교환 (사이즈는 이유) |
| 불량이에요. 환불해 주세요. | 반품·환불 | 요청이 환불 |
| 받은 지 3일 만에 전원이 안 켜져요. 불량인 것 같아요. | 상품 | 요청 없음 → 원인(상품 하자) |
| 배송이 너무 늦어요. 그냥 취소해 주세요. | 주문 취소 | 요청이 취소 (지연은 이유) |
| 사이즈가 생각보다 작네요. | 상품 | 요청 없음 → 원인(사이즈) |

### 원칙 2. 이미 진행 중인 건은 **처음 신청한 처리**의 유형

교환·반품·취소를 신청한 뒤의 회수, 택배비, 환불 지연, 철회 문의는 처음 신청한 처리를 따릅니다.

| 문장 | 유형 |
| --- | --- |
| 교환 접수했는데 회수 기사님이 아직 안 오셨어요. | 교환 |
| 교환 배송비는 제가 부담해야 하나요? | 교환 |
| 반품 보낸 지 일주일이 넘었는데 아직 환불이 안 됐어요. | 반품·환불 |
| 환불을 적립금 말고 카드로 받고 싶어요. | 반품·환불 |
| 반품 신청한 거 취소해 주세요. | 반품·환불 (취소 대상이 반품) |
| 주문 취소했는데 카드 승인 취소가 아직 안 됐어요. | 주문 취소 |
| 취소하면 카드 결제도 바로 취소되나요? | 주문 취소 |

### 원칙 3. 결제 과정의 오류는 요청이 '취소'여도 **결제**

| 문장 | 유형 | 이유 |
| --- | --- | --- |
| 같은 주문이 두 번 결제됐어요. 하나 취소해 주세요. | 결제 | 원인이 결제 오류 (주문을 없애려는 것이 아님) |
| 결제하다가 오류가 났는데 돈은 빠져나갔어요. | 결제 | |
| 주문은 유지하고 결제 수단만 카드로 바꾸고 싶어요. | 결제 | |
| 실수로 두 개 주문했어요. 하나 취소해 주세요. | 주문 취소 | 주문 자체를 없앰 |

### 원칙 4. 할인은 **누가 주는 혜택인지**로 정한다

| 혜택을 주는 곳 | 유형 | 예 |
| --- | --- | --- |
| 카드사·결제 수단 | 결제 | 청구할인, 카드 즉시할인, 무이자 할부, 간편결제 할인 |
| 쇼핑몰 | 쿠폰·적립금·회원 | 쿠폰, 적립금, 포인트, 등급 할인, 자동주문·앱 주문 할인, 이벤트 할인 |

| 문장 | 유형 |
| --- | --- |
| 농협카드로 결제하면 청구할인도 적용되나요? | 결제 |
| 카드 등록하면 할인을 받아요? | 결제 |
| 자동 주문하면 천원 할인인가요? | 쿠폰·적립금·회원 |
| 적립금 만원 쓰고 나머지는 무통장 입금할게요. | 결제 (결제 방법을 정하는 문장) |
| 주문 취소하면 사용한 쿠폰은 돌려받을 수 있나요? | 쿠폰·적립금·회원 (혜택이 어떻게 되는지 묻는 문장) |

### 원칙 5. 배송 단어가 있어도 **첫 배송**이 아니면 배송이 아니다

| 문장 | 유형 | 이유 |
| --- | --- | --- |
| 다른 사람 물건이 왔어요. | 배송 | 오배송은 배송 사고 (요청이 반품이면 원칙 1) |
| 택배가 파손된 채로 왔어요. | 배송 | 배송 사고 |
| 반품 택배는 제가 직접 보내야 하나요? | 반품·환불 | 반품 과정 (원칙 2) |
| 회수해 가고 다시 배송해 주는 거죠? | 교환 | 교환 과정 (원칙 2) |
| 제주도는 배송비가 추가되나요? | 배송 | 첫 배송 |

### 원칙 6. 재고·유통기한·사양은 **상품**

| 문장 | 유형 |
| --- | --- |
| 이 원피스 재입고 언제 되나요? | 상품 (입고 ≠ 배송) |
| 유통기한이 얼마나 남은 제품이 배송되나요? | 상품 |
| 이 청소기 AS 기간이 어떻게 되나요? | 상품 |
| 상품 출고는 언제 되나요? | 배송 |

### 원칙 7. 기타와 다른 유형의 경계

| 문장 | 유형 | 이유 |
| --- | --- | --- |
| 방송 중인 상품을 주문하고 싶어요. | 기타 | 새 주문 방법 |
| 주문하려는데 카드 결제가 안 돼요. | 결제 | 주문 중이라도 결제 문제 |
| 주문하려는데 쿠폰 적용이 안 돼요. | 쿠폰·적립금·회원 | 주문 중이라도 쿠폰 문제 |
| 앱이 자꾸 튕겨요. | 기타 | 앱 오류 |
| 로그인이 계속 안 돼요. | 쿠폰·적립금·회원 | 계정 문제 |
| 마케팅 문자 수신 거부하고 싶어요. | 기타 | 알림 설정 |
| 회원 정보에서 전화번호를 바꾸고 싶어요. | 쿠폰·적립금·회원 | 회원 정보 |
| 선물 포장 서비스가 있나요? | 기타 | 부가 서비스 |
| 선물 받은 상품을 다른 상품으로 바꿀 수 있나요? | 교환 | 요청이 교환 (원칙 1) |
| 상담원이 불친절했어요. | 기타 | 서비스 불만 |
| 리뷰를 삭제하고 싶어요. | 기타 | 게시판 |
| 상세페이지에는 70W라고 돼 있고 옵션 선택란에는 50W라고 돼 있어요. 어떤 게 맞나요? | 기타 | 페이지 표기 오류 (아래) |
| 상품설명에 양쪽 수유 가능하다고 나와 있는데 커넥터 없이도 되나요? | 상품 | 사양 질문 (아래) |

**상품 페이지 표기 문제** (2026-11-13 추가)

| 문의 | 유형 | 이유 |
| --- | --- | --- |
| 페이지의 **표기 자체가 틀렸거나 서로 다르다**고 알림 (상세 설명 ↔ 옵션, 사진 ↔ 상품명, 페이지마다 가격·용량이 다름, 다른 상품 설명이 나옴) | 기타 | 직원이 정확한 사양을 확인하고 페이지를 고쳐야 하는 **운영 문의**. FAQ로 답할 수 없어 담당자 연결이 맞음 |
| 설명을 근거로 **상품의 사양·사용 가능 여부를 물음** (표기가 틀렸다는 말은 없음) | 상품 | 상품 정보로 답할 수 있는 질문 |
| 구매 전에 **사진과 실물**이 다른지 물음 ("상세페이지 색상이랑 실제 색상이 많이 다른가요?") | 상품 | 상품 자체에 대한 질문 |
| **받은 상품**이 설명과 다름 | 원칙 1 | 교환·반품 요청이 있으면 그 유형, 없으면 상품 (다른 상품이 왔으면 배송: 오배송) |

판단이 어려우면 "고객이 알려주는 것이 **페이지의 잘못**인가(기타), **상품에 대한 궁금증**인가(상품)"로 정합니다.
표기된 것이 **쿠폰 적용가·할인가**이면 쿠폰 문제로 보고 원칙 4·7에 따라 쿠폰·적립금·회원(카드사 할인이면 결제)입니다.
지금 학습 데이터(소상공인 데이터의 웹사이트 문의 104건 → 기타, 사양 질문 → 상품)와 외부 테스트가 이미 이 기준을 따르고 있습니다.
Zero-shot LLM은 이 경계에서 페이지 표기 오류를 상품으로 판단하는 경우가 많았습니다 (외부 테스트 오답 110건 중 33건).

### 원칙 8. 여러 내용이 섞이면 **주된 요청 하나**

- 질문과 인사가 섞이면 질문의 유형: "빨리 보내주셔서 감사해요! 그런데 양말이 안 왔어요." → 배송
- 감사 인사만 있으면 **무엇에 대한 감사인지**: "환불 처리 빨리 해주셔서 감사합니다." → 반품·환불
- 대상이 없는 일반 칭찬·감사: "항상 잘 이용하고 있어요." → 기타
- 요청이 두 개면 먼저 처리해야 하는 것: "주소도 바뀌었고 카드도 바뀌었어요." → 배송 (배송지가 틀리면 상품을 못 받음)

### 원칙 9. 그래도 정할 수 없으면 학습 데이터에서 뺀다

맥락 없이는 사람도 유형을 알 수 없는 문장("그럼 그걸로 해주세요", "씨제이택배 맞죠?")은 학습 데이터에 넣지 않습니다.
웹 문의 폼에는 이런 문장이 거의 오지 않고, 억지로 라벨을 붙이면 오히려 모델이 헷갈립니다.

## 3. 감정 기준

| 감정 | 기준 | 예 |
| --- | --- | --- |
| 부정 | 불만·불편을 **드러내는** 문장. 감정 표현, 반복·지연 강조("계속", "아직도", "벌써 두 번째"), 손해 호소, 항의·신고 언급 | 일주일째 배송 준비중이에요. 도대체 언제 보내주실 건가요? |
| 중립 | 문제가 있어도 **담담하게 묻거나 요청**하는 문장 | 송장번호가 조회가 안 됩니다. |
| 긍정 | 감사·칭찬·만족 표현 | 친절하게 교환 처리해주셔서 감사해요. |

- 감정은 유형과 따로 정합니다. "환불 처리 감사합니다"는 유형은 반품·환불, 감정은 긍정입니다.
- 긴급도 규칙(`backend/ai/rules.py`)이 부정 감정을 쓰므로, 단순한 문제 신고까지 부정으로 붙이지 않습니다.

## 4. 현재 데이터와의 차이 (알려진 문제)

콜센터 데이터는 `prepare_data.py`가 **고객의도 이름의 단어**로 자동 라벨링하므로 이 기준과 다른 경우가 있습니다.
2026-11-12 기준 모델이 콜센터 평가 데이터에서 틀린 77건 중 상당수가 모델이 아니라 라벨 문제였습니다.

| 자동 라벨 | 기준에 따른 정답 | 원인 | 평가 데이터 오류 건수 |
| --- | --- | --- | --- |
| 쿠폰·적립금·회원 | 결제 | 고객의도에 '할인'만 있고 카드사 할인 (원칙 4) | 15 |
| 상품 | 교환·반품·환불 | 고객의도가 '사이즈불만' 등인데 문장에 교환·반품 요청 (원칙 1) | 약 10 |
| 배송 | 교환·반품·환불 | 교환·반품 과정의 택배비·재배송 (원칙 2) | 약 5 |

### 적용한 보정 규칙 (`prepare_data.py`의 `correct_category`, 규칙 5)

| 보정 | 조건 | 보정 건수 (중복 제거 전) |
| --- | --- | --- |
| 원칙4_카드사할인 | 쿠폰·적립금·회원 + 의도에 '할인' + 문장에 카드·청구·무이자·할부·일시불·페이, 쇼핑몰 혜택 단어 없음 → 결제 | 208 |
| 원칙1_교환요청 / 원칙1_반품요청 | 상품 + 문장에 교환(또는 반품·환불) 중 하나만 있음 → 그 유형 | 166 / 81 |
| 원칙2_교환과정 / 원칙2_반품과정 | 배송 + 문장에 '교환'(또는 반품·환불) 중 하나만 있음 → 그 유형 | 84 / 61 |
| 원칙9_판단불가 | 배송 + 교환·반품 단어 없이 회수·수거만 있음 → 학습에서 제외 | 77 |

- 배송 문장의 "바꿔 주세요"는 대부분 **배송지 변경**이라, 배송 문장은 '교환'이라는 단어가 있을 때만 교환으로 바꿉니다.
- 단어로 판단하므로 완벽하지 않습니다. 예) "교환은 안 되고 AS를 안내받았어요"처럼 교환을 **언급만** 한 문장도 교환으로 바뀔 수 있습니다.
- 보정된 문장은 `data/raw/inquiries.csv`의 `label_rule` 컬럼에 원칙 이름이 남아 있어 따로 검토할 수 있습니다.

### 보정 효과 (2026-11-12, KoELECTRA, 대화 단위 분할)

| 평가 | 보정 전 | 보정 후 |
| --- | --- | --- |
| 콜센터 평가 데이터 정확도 | 95.1% | 97.0% |
| 결제 F1 / 쿠폰·적립금·회원 F1 | 0.937 / 0.926 | 0.959 / 0.976 |

콜센터 평가 데이터는 정답 라벨도 함께 보정되었으므로, 점수가 오른 데에는 정답이 정확해진 영향도 포함되어 있습니다.
실전 테스트 100건은 라벨이 바뀌지 않았으므로 순수한 개선 효과로 볼 수 있습니다.

### 아직 남은 차이

- 주문 취소 후 "카드 취소가 왜 안 와요?" 같은 문장은 원칙 2에 따르면 주문 취소지만, 콜센터 데이터에서는 고객의도에 '카드'가 있어 결제로 남아 있습니다. 주문 취소인지 결제 취소인지 문장만으로 구분하기 어려워 보정하지 않았습니다.

## 5. 다른 데이터의 변환 규칙

콜센터 데이터 외에 추가한 데이터도 같은 기준(1~3장)에 맞춰 변환합니다. 규칙은 코드에 있고, 여기에는 무엇을 왜 그렇게 정했는지 남깁니다.

### 소상공인 고객 주문 질의-응답 (`prepare_qa_data.py`)

고객이 상품 Q&A에 직접 쓴 짧은 질문이라 실제 서비스(웹 문의) 말투와 같습니다. 인텐트(예: `배송_날짜_질문`)의 앞부분으로 유형을 정합니다.

| 인텐트 | 유형 | 비고 |
| --- | --- | --- |
| `결제_취소_*` | 버림 | 주문 취소인지 결제 취소인지 애매 |
| `주문_취소_*`, `구매_취소_*` | 주문 취소 | |
| `교환\|반품\|환불_*` | 교환 / 반품·환불 | 문장에 '교환'만 있으면 교환, '반품·환불'만 있으면 반품·환불, 둘 다 있거나 없으면 버림 |
| `배송_*` | 배송 | |
| `결제_*` | 결제 | 원칙 4 적용 (아래) |
| `제품_*` | 상품 | |
| `멤버십_*` | 쿠폰·적립금·회원 | 원칙 4 적용 |
| `행사_*` | 쿠폰·적립금·회원 | 쇼핑몰 할인 행사는 원칙 4에 따라 쿠폰. 혜택 단어(쿠폰·할인 등)가 없으면 버림. 쿠폰 학습 문장 2,000건 중 500건까지만 사용 (많으면 쿠폰 유형이 할인 행사 위주로 바뀜) |
| `웹사이트_*` | 기타 | 로그인·회원·적립 단어가 있으면 쿠폰·적립금·회원. 웹·앱 단어가 없거나, **배송·결제·교환·반품·취소 단어가 있으면 버림** ("택배사 사이트에 송장 조회가 안 돼요"는 배송) |
| 그 밖 (AS, 매장 등) | 버림 | |

**공통 조건**
- 음식점·카페·병원·슈퍼 같은 오프라인 매장 질문은 뺍니다.
- 유형마다 문장에 근거 단어(`prepare_data.py`의 `TEXT_EVIDENCE`)가 있어야 하고, 교환·반품·취소처럼 다른 유형 단어가 섞이면 뺍니다.
- **원칙 4 (할인 주체):** 결제·쿠폰 문장에 쇼핑몰 혜택 단어(쿠폰·적립·포인트·등급·회원·멤버십, '비회원'은 제외)만 있으면 쿠폰·적립금·회원, 카드사·결제수단 단어만 있으면 결제, 둘 다 있으면 버립니다. 행사 문장의 '카드'는 메모리카드·그래픽카드 증정이 많아 결제로 바꾸지 않고 버립니다.
- 원래 데이터의 '결제_할인_질문'에는 쇼핑몰 쿠폰 문의가 섞여 있어, 원칙 4를 적용하기 전에는 외부 테스트에서 쿠폰 문의를 결제로 10건 틀렸습니다 (적용 후 0~2건).

**감성 라벨:** `m`(중립)과 `n`(부정)이 있지만 기준이 이 가이드와 달라 감정 모델 학습에는 쓰지 않습니다. 중립 라벨에 "안내도 없이 마음대로 취소하신 겁니까?" 같은 불만 문장이 섞여 있고, 섞어서 학습하면 실전 테스트 감정 정확도가 93%에서 89%로 떨어졌습니다.

**외부 테스트:** Validation 데이터를 같은 규칙으로 변환해 유형별 100건(기타 53건)을 뽑습니다. 행사 문장은 넣지 않습니다. 정답이 인텐트에서 자동으로 만들어진 것이라 판매자 답변처럼 보이는 문장 등 잡음이 몇 % 섞여 있습니다.

### 용도별 목적대화 (`prepare_qa_data.py`)

쇼핑 대화에서 사람이 '부정감정표현하기'로 표시한 고객 문장 553건만 감정(부정) 보충으로 씁니다. 유형 학습에는 쓰지 않습니다 (콜센터 데이터와 같은 통화 말투라 효과가 작음).

### LLM 생성 기타 문의 (`generate_other.py`)

공개 데이터에 웹 서비스의 기타 문의가 없어 1장의 기타 정의를 하위 유형 12개로 나눠 생성했습니다 (입점·제휴, 고객센터 이용, 개인정보, 앱·웹 오류, 알림 설정, 부가 서비스, 게시판·리뷰, 서비스 불만, 칭찬·건의, 회사·매장 정보, 이벤트 참여, 새 주문 방법).

**걸러내는 문장**
- 다른 유형의 근거 단어(배송·결제·교환·반품·취소·쿠폰·로그인 등)가 있는 문장 (원칙 7)
- 상품 단어(상품·제품·실물·사이즈·색상·가격·옵션 등)가 있는 문장 ("사진이 실물과 달라요"는 상품)
- 기존 학습·테스트 데이터와 겹치는 문장
- 문장 끝에 따로 붙은 인사("…가능해요? 부탁드립니다")는 떼어 냅니다. 생성 문장의 35%가 이렇게 끝나서, 그대로 두면 모델이 "끝이 감사합니다면 기타"로 잘못 배웁니다. 떼어낼 수 없는 끝맺음("차단 부탁드립니다")은 직접 쓴 보충 데이터 수준인 7%까지만 남깁니다.

생성 문장의 감정은 `label_sentiment.py`가 이 가이드 3장 기준으로 다시 붙입니다 (사람이 쓴 보충 데이터만 사람 라벨을 그대로 유지).
