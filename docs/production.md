# 실서비스로 바꿀 때 (지금 구조와 다음 단계)

InquAI는 **시연·교육용으로 한 대의 컴퓨터에서 돌아가게** 만들었습니다. 실제 쇼핑몰에 붙인다면 아래를 바꿉니다.
"지금 이미 한 것"과 "바꿀 것"을 나눠 적었습니다 (2026-11-26).

## 한눈에 보기

| 항목 | 지금 | 실서비스 | 상태 |
| --- | --- | --- | --- |
| DB | SQLite 파일 하나 (`data/inquai.db`) | PostgreSQL | **확인함**: 테스트 전체를 PostgreSQL 17에서 통과 (아래 1) |
| DB 구조 바꾸기 | 서버가 켜질 때 새 칸만 자동으로 붙임 (`session.py`) | Alembic(구조 변경 기록·되돌리기) | 할 일 |
| 환불 계좌 열쇠 | `.env`의 열쇠, **열쇠 바꾸기 지원** | 열쇠 관리 서비스(KMS) | **일부 함**: 열쇠 바꾸기 (아래 3) |
| AI 처리 | 요청은 별도 스레드, **초안 작성은 응답 뒤로** | 대기열(Redis + 작업 프로그램) | 할 일 (아래 4) |
| 요청 제한·로그인 실패 횟수 | 서버 메모리 | Redis (서버 여러 대가 같은 값을 봄) | 할 일 |
| 첨부 사진 | 서버 폴더 (`data/uploads`) | 파일 저장소(S3 등) + 서명 주소 | 할 일 (서명 주소는 이미 씀) |
| 비밀값 | `.env` 파일 (저장소·이미지에 안 들어감, CI가 확인) | 비밀값 관리 서비스 | 할 일 |
| 오류 알림 | 서버 로그 + LangSmith(AI 처리 기록) | 오류 알림 서비스(Sentry 등) | 할 일 |

## 1. PostgreSQL

- 설정은 처음부터 바꿀 수 있게 되어 있습니다: `.env`의 `DATABASE_URL=postgresql+psycopg://사용자:비밀번호@주소/inquai`.
  연결 패키지 `psycopg[binary]`는 `requirements.txt`에 있습니다.
- **확인한 방법 (2026-11-26)**: Docker로 PostgreSQL 17을 띄우고 백엔드 테스트 전체를 그 DB로 돌렸습니다.
  ```powershell
  docker run -d --name inquai-pgtest -e POSTGRES_PASSWORD=pgtest-only -e POSTGRES_DB=inquai_test -p 127.0.0.1:55432:5432 postgres:17-alpine
  ```
  ```powershell
  $env:TEST_DATABASE_URL = "postgresql+psycopg://postgres:pgtest-only@127.0.0.1:55432/inquai_test"; .venv\Scripts\python -m pytest backend/tests -q
  ```
  테스트는 `TEST_DATABASE_URL`이 있으면 그 DB를 씁니다 (`backend/tests/conftest.py`). **테스트마다 표를 지우고 다시 만들므로 빈 시험용 DB에만** 쓰세요.
- 결과: **324개 모두 통과** (그 뒤 테스트가 늘어 지금은 330개, CI가 매번 확인) (4분 30초, SQLite와 같은 결과). GitHub 자동 검사에도 'PostgreSQL 테스트'를 넣어 푸시할 때마다 확인합니다.
- 남은 차이: 서버가 켜질 때 새 칸을 자동으로 붙이는 기능은 SQLite에서만 동작합니다. PostgreSQL에서는 Alembic으로 바꿉니다 (2).

## 2. DB 구조 바꾸기 (Alembic)

- 지금: 모델에 칸을 더하면 서버가 켜질 때 `ALTER TABLE … ADD COLUMN`으로 붙입니다 (비어도 되는 새 칸만). 칸 이름 바꾸기·지우기·자료형 바꾸기는 못 합니다.
- 실서비스: Alembic으로 바꿀 때마다 "변경 기록 파일"을 만들어 저장소에 남기고, 배포할 때 차례로 적용합니다. 잘못되면 되돌릴 수 있습니다.
- 시연에는 효과가 없어 하지 않았습니다.

## 3. 환불 계좌 열쇠

- 지금 한 것: 예금주·계좌번호를 Fernet으로 암호화해 저장 (`backend/services/refund_account.py`).
  **열쇠 바꾸기**: 새 열쇠는 `REFUND_ACCOUNT_KEY`, 예전 열쇠는 `REFUND_ACCOUNT_OLD_KEYS`에 넣고 서버를 켜면 예전 열쇠로 잠긴 계좌를 새 열쇠로 다시 잠급니다.
  그 뒤에는 예전 열쇠를 지워도 됩니다. 열쇠가 새어 나갔을 때 바로 바꿀 수 있습니다.
- 실서비스: 열쇠를 `.env`가 아니라 열쇠 관리 서비스(AWS KMS 등)에 두고, 서버는 쓸 때만 받아 옵니다. 환불이 끝난 계좌는 일정 기간 뒤 지웁니다.

## 4. AI 처리 대기열

- 지금 한 것: 문의 등록 요청은 별도 스레드에서 돌아 다른 요청을 막지 않습니다. **답변 초안 작성(10초 안팎)은 고객에게 응답한 뒤에** 씁니다 (`backend/services/drafts.py`).
  고객이 기다리는 것은 자동 답변을 만들 때(약 9초)뿐입니다.
- 언제 필요한가: 1초에 4~5건 넘게 계속 들어오거나, 배송·결제 장애로 문의가 몇 분 사이에 몰릴 때.
- 바꾸면 좋아지는 것: 몰려도 다른 화면이 느려지지 않음, 서버가 다시 켜져도 하던 일을 이어서 함, OpenAI 오류 때 다시 시도, 동시 호출 수 조절(사용 한도), 긴급 문의 먼저.
- 바꾸면 달라지는 것: 고객은 "접수"를 먼저 보고 답변은 화면이 다시 확인해서 받습니다 (지금은 등록 화면에서 바로 받음). Redis와 작업 프로그램을 따로 운영해야 합니다.
- 시연(사용자 한 명)에서는 차이가 보이지 않고 장면 2(바로 답변)가 한 단계 늘어나서, 제출 전에는 하지 않았습니다.
