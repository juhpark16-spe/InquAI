# 테스트

InquAI에는 세 종류의 자동 테스트가 있고, main에 푸시할 때마다 GitHub Actions(`.github/workflows/ci.yml`)가 모두 실행합니다.
모델 정확도·에이전트 판단 평가는 따로 합니다 (`docs/model_card.md`, `evaluation/`).

| 종류 | 무엇을 확인하나 | 실행 (프로젝트 루트에서) | CI 작업 이름 |
| --- | --- | --- | --- |
| 백엔드 테스트 (pytest, 270개) | API·권한·에이전트 흐름·보안 규칙 | `python -m pytest backend/tests -q` | 백엔드 테스트 |
| 화면 자동 테스트 (Playwright, 11개) | 실제 브라우저로 화면을 눌러 핵심 흐름 확인 | `cd frontend` 후 `npm run test:e2e` | 화면 자동 테스트 |
| Docker 확인 | 이미지 빌드, 비밀값·모델이 이미지에 없는지, 켜서 응답하는지 | (CI 전용, `docs/docker.md` 5절) | Docker 빌드 |

그 밖에 CI는 화면 타입 검사·빌드, npm·파이썬 패키지 취약점 검사도 합니다 (`docs/security_audit.md`).

## 화면 자동 테스트 (Playwright)

`frontend/e2e/inquiry-flow.spec.ts`

| 테스트 | 흐름 |
| --- | --- |
| 고객 문의 → 상담원 답변 발송 → 고객 조회에서 답변 확인 | 비회원 문의 등록 → 문의 번호 확인 → 관리자 로그인 → 위쪽 검색창('/' 키)에 문의 번호 → 상세 화면으로 바로 → 답변 작성·발송 → 고객이 이메일·조회 비밀번호로 조회하면 상담원 답변이 보임 (입력 카드는 '문의 1건 · 답변 완료 1' 한 줄 띠로 접힘) → [조회 끝내기]로 결과·입력 지움 |
| 배정받은 상담원의 알림 종에 새 문의가 뜨고, 누르면 상세로 | 고객이 '배송' 문의 등록 → 배송 담당 상담원(agent2)에게 자동 배정 → agent2 로그인 시 🔔에 숫자 → 열면 숫자가 사라지고 목록에 문의 → 누르면 상세 |
| 회원 주문 취소 요청 → 상담원 취소 티켓 승인·문구 넣어 발송 → 고객 화면에서 주문 취소·답변 완료 | 쇼핑몰 회원 로그인 → 내 쇼핑의 '결제 완료' 주문 [이 주문 문의하기] → 취소 요청 → (다른 창) 주문 취소 담당 상담원이 문의 번호 검색 → 주문 정보 '취소 가능' 확인 → [취소 승인] → 주문이 '이미 취소된 주문'으로 → 답변 문구 '취소 완료' 넣어 발송 → 고객의 내 쇼핑에서 주문 '취소'·문의 '답변 완료' |
| 출고 전 배송지 변경 요청 → 상담원이 [바로 처리]로 배송지 변경 → 처리 이력에 남음 | 회원(장시우)이 출고 전 주문에서 배송지 변경 문의 → 배송 담당 상담원이 검색 → 바로 처리 [배송지 변경] → 결과 안내와 주문 정보의 배송지가 바뀜 |
| 확인 후 다시 안내 → 표시·목록 필터 → 고객에게 '추가 안내 예정' | 비회원 일반 문의(재입고 일정) → 관리자가 '확인 후 안내' 답변을 쓰면 체크 권유 → [🔁 확인 후 다시 안내] 체크·확인할 내용·기한 [내일 오전 10시] → 발송 → 답변 칸 위 다시 안내 표시, 목록 `?recheck=true`에 보임 → 고객 조회에 '추가 안내 예정' (확인할 내용은 안 보임) |
| 파손 문의는 송장·파손 부위 사진 두 장이 있어야 등록 | 내용에 '깨져서 왔어요' → 사진 두 칸(송장·파손 부위) → 사진 없이 [문의 등록]하면 안내 → 두 장 올리면 등록 / '지금은 사진이 없어요' 체크하면 사진 없이 등록하고 [추가 문의하기] 안내 |
| 비회원 문의 표시 · 주문번호 형식 확인 | 로그인하지 않은 문의 화면에 '비회원 문의'·[회원 로그인] → 주문번호 `20261120-022`는 빨간 안내 → 12자리 숫자는 칸을 벗어나면 `20261120-0022`로 |
| 조회 비밀번호가 틀리면 문의가 보이지 않음 | 다른 비밀번호로 조회하면 문의 내용이 화면에 나오지 않음 |
| 여러 건이 찾아지면 문의 목록에 검색어와 함께 보여 줌 | 위쪽 검색창에 단어 → 문의 목록 `?q=` + "검색어: …" 표시 → ✕로 지우기 |
| 상담원은 관리자 전용 화면에 들어갈 수 없음 | 상담원이 `/admin/users`에 들어가면 문의 목록으로 돌려보냄 |
| 로그인하지 않으면 관리 화면 대신 로그인 화면 | `/admin/inquiries` → `/login` |

**개발 서버·개발 DB와 섞이지 않게**
- Playwright가 테스트할 때마다 **시험용 백엔드**(`backend/tests/e2e_server.py`, 포트 8001)와 화면 서버(포트 5174)를 새로 켜고 끝나면 끕니다.
- 시험용 백엔드는 한 IP에서 문의를 여러 건 만들기 때문에 **문의 등록 횟수 제한(1분 5건)만** 끕니다 (다른 제한은 그대로).
  개발 중인 서버(8000, 5173)를 켜 둔 채로 실행해도 됩니다.
- 시험용 백엔드는 임시 폴더에 새 DB를 만들고 관리자·상담원 계정, FAQ, 모의 주문만 넣습니다. 개발 DB(`data/inquai.db`)와 첨부 사진 폴더는 건드리지 않습니다.
- 분류 모델·KURE·OpenAI·LangSmith는 쓰지 않습니다 (CI에는 모델과 API 키가 없음). 분류는 단어 규칙으로 하는 가짜 분석기,
  LLM 판단·초안은 늘 같은 답을 주는 가짜 LLM이 대신해 결과가 늘 같습니다. 가짜 LLM은 자동 답변을 하지 않고 처리 경로에 맞는 도구로 '답변 초안'
  (예: 주문 취소 → 티켓 접수)을 골라, 모든 문의가 담당자에게 갑니다. 그래서 이 테스트는 **화면 흐름**을 확인하는 것이고 AI 정확도와는 관계없습니다.
- 시험용 계정 비밀번호는 코드에 적힌 시험 전용 값입니다 (`E2E_PASSWORD` 환경 변수로 바꿀 수 있음). 임시 DB에만 있고 테스트가 끝나면 쓰지 않습니다.

**처음 한 번 준비**
```bash
cd frontend
npm install
npx playwright install chromium
```

**실패했을 때**
- 실패한 테스트의 스크린샷과 trace(화면 기록)가 `frontend/test-results/`에 남습니다. `npx playwright show-trace <trace.zip 경로>`로 한 단계씩 다시 볼 수 있습니다.
- CI에서 실패하면 같은 파일을 `playwright-report` 아티팩트로 올려 7일 보관합니다.
- 문의 등록은 1분에 5건까지라(요청 제한) 테스트는 한 번에 하나씩 차례로 실행합니다.
