# 테스트

InquAI에는 세 종류의 자동 테스트가 있고, main에 푸시할 때마다 GitHub Actions(`.github/workflows/ci.yml`)가 모두 실행합니다.
모델 정확도·에이전트 판단 평가는 따로 합니다 (`docs/model_card.md`, `evaluation/`).

| 종류 | 무엇을 확인하나 | 실행 (프로젝트 루트에서) | CI 작업 이름 |
| --- | --- | --- | --- |
| 백엔드 테스트 (pytest, 234개) | API·권한·에이전트 흐름·보안 규칙 | `python -m pytest backend/tests -q` | 백엔드 테스트 |
| 화면 자동 테스트 (Playwright, 5개) | 실제 브라우저로 화면을 눌러 핵심 흐름 확인 | `cd frontend` 후 `npm run test:e2e` | 화면 자동 테스트 |
| Docker 확인 | 이미지 빌드, 비밀값·모델이 이미지에 없는지, 켜서 응답하는지 | (CI 전용, `docs/docker.md` 5절) | Docker 빌드 |

그 밖에 CI는 화면 타입 검사·빌드, npm·파이썬 패키지 취약점 검사도 합니다 (`docs/security_audit.md`).

## 화면 자동 테스트 (Playwright)

`frontend/e2e/inquiry-flow.spec.ts`

| 테스트 | 흐름 |
| --- | --- |
| 고객 문의 → 상담원 답변 발송 → 고객 조회에서 답변 확인 | 비회원 문의 등록 → 문의 번호 확인 → 관리자 로그인 → 위쪽 검색창('/' 키)에 문의 번호 → 상세 화면으로 바로 → 답변 작성·발송 → 고객이 이메일·조회 비밀번호로 조회하면 상담원 답변이 보임 |
| 조회 비밀번호가 틀리면 문의가 보이지 않음 | 다른 비밀번호로 조회하면 문의 내용이 화면에 나오지 않음 |
| 여러 건이 찾아지면 문의 목록에 검색어와 함께 보여 줌 | 위쪽 검색창에 단어 → 문의 목록 `?q=` + "검색어: …" 표시 → ✕로 지우기 |
| 상담원은 관리자 전용 화면에 들어갈 수 없음 | 상담원이 `/admin/users`에 들어가면 문의 목록으로 돌려보냄 |
| 로그인하지 않으면 관리 화면 대신 로그인 화면 | `/admin/inquiries` → `/login` |

**개발 서버·개발 DB와 섞이지 않게**
- Playwright가 테스트할 때마다 **시험용 백엔드**(`backend/tests/e2e_server.py`, 포트 8001)와 화면 서버(포트 5174)를 새로 켜고 끝나면 끕니다.
  개발 중인 서버(8000, 5173)를 켜 둔 채로 실행해도 됩니다.
- 시험용 백엔드는 임시 폴더에 새 DB를 만들고 관리자·상담원 계정, FAQ, 모의 주문만 넣습니다. 개발 DB(`data/inquai.db`)와 첨부 사진 폴더는 건드리지 않습니다.
- 분류 모델·KURE·OpenAI·LangSmith는 쓰지 않습니다 (CI에는 모델과 API 키가 없음). 분류는 단어 규칙으로 하는 가짜 분석기가 대신해 결과가 늘 같고,
  LLM이 없어 자동 답변 없이 모든 문의가 담당자에게 갑니다. 그래서 이 테스트는 **화면 흐름**을 확인하는 것이고 AI 정확도와는 관계없습니다.
- 시험용 계정 비밀번호는 코드에 적힌 시험 전용 값입니다 (`E2E_PASSWORD` 환경 변수로 바꿀 수 있음). 임시 DB에만 있고 테스트가 끝나면 쓰지 않습니다.

**처음 한 번 준비**
```bash
cd frontend
npm install
npx playwright install chromium
```

**실패했을 때**
- 실패한 테스트의 스크린샷과 trace(화면 기록)가 `frontend/test-results/`에 남습니다. `npx playwright show-trace <trace.zip 경로>`로 한 단계씩 다시 볼 수 있습니다.
- CI에서 실패하면 같은 파일을 `playwright-report` 아티팩트로 올려 7일 보관합니다.
- 문의 등록은 1분에 5건까지라(요청 제한) 테스트는 한 번에 하나씩 차례로 실행합니다.
