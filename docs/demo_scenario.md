입력 문장은 실제 모델·LLM으로 돌려 결과를 확인한 것입니다 (아래 "확인 결과").

**핵심 이야기** (`docs/project_scope.md`): "AI가 답할 수 있는 문의는 바로 답하고, 위험한 문의는 사람에게 넘기며, 사람이 고친 결과는 다시 AI를 좋게 만든다."
장면 순서도 이 세 부분을 따릅니다: **① 바로 답한다(장면 2) → ② 위험하면 사람에게(장면 3~6) → ③ 사람의 수정이 AI로(장면 7)**.

전체 길이 목표: **약 7분 30초** (장면 1~9). 주문 처리 같은 배경 기능은 맨 아래 **부록 장면**으로 옮겼습니다 (녹화하지 않거나 질의응답용).

## 0. 녹화 전 준비 (녹화 30분 전)

1. **시연 DB 새로 만들기 (녹화 직전에)**: 기한·알림이 '지금' 기준으로 만들어집니다. 하루만 지나도 기한이 지나 화면이 바뀝니다 (`docs/db_schema.md`).
   ```powershell
   .venv\Scripts\python -m backend.database.seed_demo --reset
   ```
   ```powershell
   .venv\Scripts\python -m backend.training.seed_corrections
   ```
   두 번째 명령은 재학습 현황 화면에 '상담원 분류 수정' 기록을 채웁니다 (`docs/retraining.md`).
   - **녹화는 평일에**: 답변 기한은 주말(토·일)을 세지 않아, 주말에 녹화하면 기한이 월요일로 밀려 '기한 임박'·🔔 기한 알림 장면이 나오지 않습니다
2. **백엔드 서버 다시 켜기** (새 DB의 FAQ를 읽도록). 화면은 `http://localhost:5173`
3. **브라우저 두 개**: 고객용 창과 직원용 창을 따로 엽니다 (크롬 일반 창 + 다른 프로필 또는 시크릿 창). 로그인이 섞이지 않게
4. **화면 크기 1440×900, 확대 100%**. 알림·확장 프로그램 아이콘은 숨깁니다
5. 계정과 비밀번호 (비밀번호 값은 `.env`에 있음, 화면에 비밀번호가 보이지 않게 미리 입력해 두거나 자동 완성)

| 역할 | 아이디 | 비밀번호 | 담당 |
| --- | --- | --- | --- |
| 관리자 | `admin` | `.env`의 `SEED_ADMIN_PASSWORD` | 전체 |
| 상담원 김하늘 | `agent1` | `.env`의 `SEED_AGENT_PASSWORD` | 주문 취소 · 반품·환불 · 결제 |
| 상담원 이준호 | `agent2` | 위와 같음 | 배송 · 교환 · 상품 |

> (회원은 내 쇼핑의 [이 주문 문의하기], 비회원은 주문번호 칸). 주문번호 없이 쓰는 비회원 예시는 쿠폰 조건·배송비처럼 **일반 질문**만.

- 시드가 만든 미처리 '결제가 두 번 됐어요'(2시간 30분 전 접수, 긴급)를 열면 주문 정보에 빨간 **중복 결제 의심** + 승인 2건(40초 간격)
  (장면 3-1에서 새로 넣은 문의는 실제로 중복 승인이 없는 주문이라 경고가 뜨지 않음)
- 바로 처리 **[중복 승인 1건 취소]** → [중복 승인 취소] → 경고가 사라지고 결제 내역에 '승인 취소 (승인번호 …)', 대화에 처리 안내 줄
- [AI 초안 만들기] → "중복 승인 1건을 취소했고 3~5영업일 안에 반영됩니다" 같은 초안 (처리 기록이 근거로 들어감)

**부록 C. 확인 후 다시 안내 (40초)** — 직원 창(김하늘)
- 🔔에 **다시 안내** 알림(기한 40분 남음) → 시드가 만든 '확인 후 안내' 문의(파손·분실·환불 중 1건)를 열면 답변 칸 위에 파란 **🔁 다시 안내할 문의 · 확인할 내용**
- 말할 것: "바로 답할 수 없어 '확인 후 안내드리겠습니다'를 먼저 보낼 때 [확인 후 다시 안내]를 체크하면, 확인할 내용과 기한이 목록·대시보드·알림에 남아 잊지 않습니다."
- 확인 결과를 담아 답변을 쓰고 [발송] → "다시 안내 표시도 풀었습니다" (체크 없이 보내면 자동으로 풀림)
- 새 문의에서 직접 보여 주려면: 답변 칸 아래 **🔁 확인 후 다시 안내** 체크 → 확인할 내용 입력, 기한 [내일 오전 10시] → [발송 · 다시 안내 표시]
  (고객 화면에는 상태가 **추가 안내 예정**으로 보임)

**부록 D. 반품 → 회수 접수 → 승인 → 환불 진행 (50초)** — 직원 창(김하늘)
- 시드가 만든 미처리 **'반품 신청할게요'**(3시간 10분 전, 배송 완료 1~5일 된 주문)를 엶
- 요청 카드: "먼저 반품 회수를 접수해 주세요" + 카드 안 **[반품 회수 접수]** → '단순 변심' → [회수 접수]
  → 카드에 "회수 접수 (단순 변심) → 회수 전"과 **[반품 승인]**이 이어서 보임 (화면 이동 없음)
- [반품 승인] → 확인창에 **환불 예정 금액(왕복 배송비 6,000원 차감) · 결제 수단별 환불 기간**
  - '검수 결과 불량 → 배송비 차감 없이 전액 환불' 체크를 켜면 금액이 전액으로 바뀌는 것도 보여 줄 수 있음
- 승인 뒤 주문 요약에 "환불 예정 n원" → 왼쪽 메뉴 **취소·교환·반품 > 환불 진행** 탭에 같은 줄
- 말할 것: "반품은 회수 접수에서 기한과 사유를 확인한 뒤에만 승인돼, 배송비 차감이 빠지지 않습니다."

**부록 E. 무통장입금 취소와 환불 계좌 (50초)** — 직원 창 → 고객 창
- 직원 창: 시드가 만든 **'무통장 입금한 주문 취소'**(4시간 30분 전)를 엶 → 요청 카드에 "💳 환불 계좌가 필요해요 · 아직 없음" + [+ 환불 계좌 요청 문구 넣기]
- 고객 창: 그 문의 고객(문의 상세의 고객 카드 이메일, 비밀번호는 `.env`의 `SEED_CUSTOMER_PASSWORD`)으로 로그인 → 내 쇼핑 > 내 문의
  → [내용 보충 · 추가 문의]에 **'무통장입금으로 결제한 주문을 취소·반품해요'가 체크된 채** 환불 계좌 칸 → 은행·예금주·**가짜 계좌번호**(예: 110-000-000000) 입력 → 보내기
  → 고객 화면에 "국민은행 ****0000 · 김*민"처럼 가려서
- 직원 창: 새로고침 → "환불 계좌 받음 ✓ (가림)" → **[번호 보기]** → 관리자 **작업 기록**에 '환불 계좌 보기'
- 말할 것: "계좌번호는 문의 글과 따로 받아 암호화해 저장하고, AI에는 넘기지 않으며, 상담원이 볼 때마다 기록이 남습니다."

**부록 G. 단순 변심 교환 배송비 (40초)** — 직원 창 → 고객 창
- 배송 완료 7일 안 주문으로 들어온 사이즈 교환 문의(예: INQ-20261125-0911 같은 문의)를 엶 → 주문 정보 바로 처리 **[교환 배송비 받기]**
  - 적립금이 6,000원 이상이면 [적립금으로 차감], 아니면 **[결제 요청 보내기]** → "교환 배송비 6,000원: 고객 결제 대기", 결제 내역에 '추가 결제'
- 고객 창(그 회원): 내 쇼핑 > 내 문의에 노란 상자 **'교환 배송비 6,000원 결제가 필요해요'** → [신용카드로 결제] (시연용 결제, 실제로 돈이 나가지 않음)
- 직원 창 새로고침 → "교환 배송비 6,000원 받음 (신용카드)" → 회수 접수·교환 승인
- 말할 것: "반품은 환불에서 빼면 되지만 교환은 돌려줄 돈이 없어, 적립금이나 결제 요청으로 받습니다. 계좌 입금처럼 확인이 번거로운 방법은 쓰지 않습니다."

**부록 F. 쇼핑몰 정보 화면 (30초)** — 직원 창
- 위쪽 검색창에 `/` → 문의 번호 입력 → 상세로 바로
- **주문·배송**: '배송 지연' 탭, 줄을 펼쳐 결제·배송 추적과 **택배사 확인(배송조회 열기·고객센터 번호·담당 기사)**
- **고객 조회**(주문·문의·쿠폰 한 화면, 조회 기록이 남음) · **재고 현황**(품절·재고 적음)
- **답변 문구**(관리자가 고치면 답변 칸에 바로 반영) · **작업 기록**(장면 5의 '취소 승인'이 '주문 … 결제 완료 → 취소'로 남음)
