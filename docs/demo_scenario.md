# 시연 시나리오 (영상 녹화용)

12/8 시연 영상을 이 순서대로 찍습니다. 장면마다 **누가 · 어디서 · 무엇을 입력하고 · 무엇이 보이는지**를 적었습니다.
입력 문장은 2026-11-20에 실제 모델·LLM으로 돌려 결과를 확인한 것입니다 (아래 "확인 결과").
PPT도 같은 순서(고객 → AI → 상담원 → 고객 → 관리자)로 만들면 영상과 발표가 맞습니다.

전체 길이 목표: **약 7분** (장면 1~8)

## 0. 녹화 전 준비 (녹화 30분 전)

1. **시연 DB 새로 만들기 (녹화 직전에)**: 기한·알림이 '지금' 기준으로 만들어집니다. 하루만 지나도 기한이 지나 화면이 바뀝니다 (`docs/db_schema.md`).
   ```powershell
   .venv\Scripts\python -m backend.database.seed_demo --reset
   ```
   ```powershell
   .venv\Scripts\python -m backend.training.seed_corrections
   ```
   두 번째 명령은 재학습 현황 화면에 '상담원 분류 수정' 기록을 채웁니다 (`docs/retraining.md`).
   - **녹화는 평일에**: 답변 기한은 주말(토·일)을 세지 않아, 주말에 녹화하면 기한이 월요일로 밀려 '기한 임박'·🔔 기한 알림 장면이 나오지 않습니다
2. **백엔드 서버 다시 켜기** (새 DB의 FAQ를 읽도록). 화면은 `http://localhost:5173`
3. **브라우저 두 개**: 고객용 창과 직원용 창을 따로 엽니다 (크롬 일반 창 + 다른 프로필 또는 시크릿 창). 로그인이 섞이지 않게
4. **화면 크기 1440×900, 확대 100%**. 알림·확장 프로그램 아이콘은 숨깁니다
5. 계정과 비밀번호 (비밀번호 값은 `.env`에 있음, 화면에 비밀번호가 보이지 않게 미리 입력해 두거나 자동 완성)

| 역할 | 아이디 | 비밀번호 | 담당 |
| --- | --- | --- | --- |
| 관리자 | `admin` | `.env`의 `SEED_ADMIN_PASSWORD` | 전체 |
| 상담원 김하늘 | `agent1` | `.env`의 `SEED_AGENT_PASSWORD` | 주문 취소 · 반품·환불 · 결제 |
| 상담원 이준호 | `agent2` | 위와 같음 | 배송 · 교환 · 상품 |
| 쇼핑몰 회원 윤지우 | `customer08@example.com` | `.env`의 `SEED_CUSTOMER_PASSWORD` | 장면 3 (고객) |
| 쇼핑몰 회원 장시우 | `customer09@example.com` | 위와 같음 | 장면 6 (고객) |

> 윤지우의 '결제 완료' 주문을 장면 3에서 씁니다. 시드가 바뀌어 없으면 내 쇼핑에서 **결제 완료 또는 상품 준비 중** 주문이 있는 다른 고객(customer02·09·15 등)을 고릅니다.

> **예시 문장 규칙**: 특정 주문을 확인해야 하는 문의(배송 상태·파손·중복 결제·환불·교환 등)는 반드시 **주문번호가 있게** 씁니다
> (회원은 내 쇼핑의 [이 주문 문의하기], 비회원은 주문번호 칸). 주문번호 없이 쓰는 비회원 예시는 쿠폰 조건·배송비처럼 **일반 질문**만.

## 장면별 진행

### 장면 1. 소개 (20초) — 화면: 고객센터 첫 화면 `/faq`
- 말할 것: "쇼핑몰 고객 문의를 AI가 분류하고, 자주 묻는 질문은 바로 답하고, 나머지는 우선순위를 정해 상담원에게 넘기는 서비스입니다."
- FAQ 유형 버튼(배송·주문 취소…)을 한두 번 눌러 보여 줍니다.

### 장면 2. AI 자동 답변 (50초) — 고객 창, 비회원 `/inquiry`
| 칸 | 입력 |
| --- | --- |
| 이름 / 이메일 | 김데모 / `demo-a@example.com` |
| 조회 비밀번호 | `demo1234` (두 칸 모두) |
| 제목 | 쿠폰 적용 |
| 문의 내용 | 신규 가입 쿠폰을 받았는데 결제할 때 적용이 안 돼요. 최소 주문 금액 조건이 따로 있나요? |

- 문의 내용을 쓰는 동안 아래에 **비슷한 FAQ 추천**이 뜨는 것을 보여 줍니다.
- 개인정보 동의 체크 → [문의 등록] → 약 **9초** 뒤 AI 답변이 대화로 나옵니다 (기다리는 동안 "분류 모델로 유형을 고르고, FAQ를 찾아 LLM이 근거 있는 답만 보냅니다" 설명).
- 보이는 것: 상태 **자동 처리**, AI 상담원 말풍선 (FAQ F05 근거)

### 장면 3. 회원의 주문 문의 → 상담원에게 (40초) — 고객 창
1. 위쪽 [로그인] → 윤지우 계정 로그인 → **내 쇼핑**
2. '결제 완료' 주문의 **[이 주문 문의하기]** → 주문번호가 미리 골라져 있음
3. 입력

| 칸 | 입력 |
| --- | --- |
| 제목 | 주문 취소 부탁드려요 |
| 문의 내용 | 방금 결제했는데 색상을 잘못 골랐어요. 아직 출고 전이면 이 주문 취소해 주세요. |

4. [문의 등록] → 약 **4초** 뒤 "문의가 접수되었습니다" (상담원 확인이 필요한 요청이라 자동 답변하지 않음)
- 말할 것: "취소처럼 실제 처리가 필요한 요청은 AI가 직접 하지 않고, 취소 티켓과 답변 초안을 만들어 담당 상담원에게 넘깁니다."

### 장면 4. 상담원 처리 (1분 40초) — 직원 창, `agent1` (김하늘)
1. 로그인 → 오른쪽 위 **🔔 숫자** (30초 안에 뜸, 안 보이면 새로고침) → 열면 "배정 · 주문 취소 부탁드려요"
2. 알림을 눌러 **문의 상세**로
   - 위: 제목, 남은 답변 기한, ◀ 1/n ▶ 처리 대기열
   - 오른쪽 위 **접수된 티켓 (취소)**, **주문 정보**: 취소 **가능 (출고 전)**
3. 티켓 **[취소 승인]** → 주문이 바로 취소됨 (주문 정보의 상태가 '취소'로, 결제 내역에 '승인 취소')
   - 주문 정보 카드의 **바로 처리**에는 출고 전이라 [배송지 변경]·[옵션 변경]도 보임 → "색상을 잘못 골랐다면 취소 대신 옵션 변경도 바로 됩니다"라고 한마디
     ([옵션 변경]을 펼치면 옵션마다 '재고 n개 / 품절 · 재입고 예정일'이 보이고, 재고가 모자란 옵션은 고를 수 없음. 아래 **옵션별 재고**에서도 확인)
4. **[✨ AI 초안 다시 만들기]** → 승인 결과를 넣은 초안 (약 10초). '발송 전에 확인할 것'과 `[확인 필요]` 표시가 있으면 고칩니다
5. 필요하면 **▸ 문구·주문 정보 넣기**에서 "취소 완료" 문구를 한 번 눌러 보여 줌
6. **[발송]** (또는 Ctrl+Enter) → "답변을 보냈습니다" → 상태 완료, 화면 아래 **[다음 미처리 문의 →]**
- 말할 것: "상담원은 주문 정보와 티켓을 한 화면에서 보고, AI 초안을 고쳐 보냅니다. 고친 정도는 관리자 화면에서 분석됩니다."

### 장면 5. 고객이 답변 확인 (30초) — 고객 창
- 내 쇼핑 → 내 문의 맨 위 "주문 취소 부탁드려요" **답변 완료** → 펼쳐서 상담원 답변 확인 → **👍 네**
- (선택) [내용 보충 · 추가 문의]로 한 줄 남기면 상담원 🔔에 '추가 문의'가 뜨는 것까지 보여 줄 수 있음

### 장면 6. 긴급 문의는 바로 사람에게 (50초) — 고객 창(회원 장시우) → 직원 창
중복 결제는 **어느 주문인지 알아야** 확인할 수 있으므로, 주문에서 바로 문의합니다 (주문번호가 자동으로 들어감).
1. 고객 창: 윤지우 [로그아웃] → 장시우(`customer09@example.com`)로 로그인 → 내 쇼핑 → '결제 완료' 또는 '상품 준비 중' 주문의 **[이 주문 문의하기]**
2. 입력

| 칸 | 입력 |
| --- | --- |
| 제목 | 결제가 두 번 됐어요 |
| 문의 내용 | 이 주문 결제할 때 오류가 나서 다시 눌렀더니 똑같은 금액으로 카드 승인 문자가 두 번 왔어요! 중복 결제된 것 같은데 당장 확인해 주세요. |

- [문의 등록] → **1~2초** 만에 접수 (돈 관련 + 부정 → 긴급, 규칙으로 바로 담당자 연결, LLM을 기다리지 않음)
- 직원 창(김하늘): 🔔 → 문의 목록 맨 위에 **높음** 배지, 답변 기한 4시간(주말은 세지 않음). 상세 화면 오른쪽 **주문 정보**에서 결제 수단·금액을 바로 확인
  (시드 데이터의 '결제가 두 번 됐어요' 문의를 열면 **승인 2건(40초 간격) + 중복 결제 의심** 경고와 승인번호를 보여 줄 수 있음.
  장면 6에서 새로 넣은 문의는 실제로 중복 승인이 없는 주문이라 경고가 뜨지 않음)

**장면 6-2 (선택, 30초). 중복 승인 바로 취소** — 직원 창(김하늘)
- 시드가 만든 미처리 '결제가 두 번 됐어요'(2시간 30분 전 접수, 긴급)를 열면 주문 정보에 빨간 **중복 결제 의심** + 승인 2건(40초 간격)
- 바로 처리 **[중복 승인 1건 취소]** → [중복 승인 취소] → 경고가 사라지고 결제 내역에 '승인 취소 (승인번호 …)', 대화에 처리 안내 줄
- [AI 초안 만들기] → "중복 승인 1건을 취소했고 3~5영업일 안에 반영됩니다" 같은 초안 (처리 기록이 근거로 들어감)

**장면 6-3 (선택, 40초). 확인 후 다시 안내** — 직원 창(김하늘)
- 🔔에 **다시 안내** 알림(기한 40분 남음) → 시드가 만든 '확인 후 안내' 문의(파손·분실·환불 중 1건)를 열면 답변 칸 위에 파란 **🔁 다시 안내할 문의 · 확인할 내용**
- 말할 것: "바로 답할 수 없어 '확인 후 안내드리겠습니다'를 먼저 보낼 때 [확인 후 다시 안내]를 체크하면, 확인할 내용과 기한이 목록·대시보드·알림에 남아 잊지 않습니다."
- 확인 결과를 담아 답변을 쓰고 [발송] → "다시 안내 표시도 풀었습니다" (체크 없이 보내면 자동으로 풀림)
- 새 문의에서 직접 보여 주려면: 답변 칸 아래 **🔁 확인 후 다시 안내** 체크 → 확인할 내용 입력, 기한 [내일 오전 10시] → [발송 · 다시 안내 표시]
  (고객 화면에는 상태가 **추가 안내 예정**으로 보임)

### 장면 7. 관리자 화면 (2분) — 직원 창, `admin`으로 다시 로그인
1. **대시보드**
   - 지금 처리할 일: **답변 기한 초과**(빨간 카드) · 긴급 미처리 · 미처리 · 검토 대기 · 미배정
   - **지금 가장 급한 문의** + [바로 처리], **기한 임박 문의** (시드가 만든 '35분 남음' 문의가 맨 위)
   - 문의 수·자동 처리율·초안 무수정 승인율·AI 처리 시간, 날짜별 유형 그래프(미처리는 빗금)
2. 위쪽 검색창에 `/` → 장면 3의 문의 번호 입력 → 상세로 바로
3. **AI 초안 분석** (`/admin/drafts`): 상담원이 AI 초안을 얼마나·어떻게 고쳐 보냈는지, 고친 예시 비교
4. **AI 실행 로그**: 문의마다 AI가 지난 단계(FAQ 검색 → 규칙 판단 → LLM 판단 → 도구), 처리 시간
5. **재학습 현황**: 상담원이 고친 분류가 쌓이면 재학습 데이터가 되는 흐름, 모델 버전별 정확도 표
6. (시간이 되면) **답변 문구**: 관리자가 상담원용 문구를 고치면 답변 칸에 바로 반영 · **작업 기록**: 로그인 실패·티켓 승인·답변 발송이 누구에 의해 언제 됐는지 (장면 4의 '취소 승인'이 '주문 … 결제 완료 → 취소'로 남은 것을 보여 줌)
- 말할 것: "관리자는 지금 급한 일과 AI 품질을 한 화면에서 보고, 상담원의 수정이 다시 모델 개선으로 이어집니다."
