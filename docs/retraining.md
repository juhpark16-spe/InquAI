# 수정 데이터로 재학습 (4주차)

상담원이 고친 분류(`label_corrections`)를 학습 데이터에 더해 다시 학습하면, 모델이 틀리던 유형이 나아지는지 보여 주는 시연입니다.
이 문서는 재학습 전 준비·기준값, 약점 보강 문장, 재학습 결과를 차례로 적습니다.
관리자 화면 **재학습 현황**(`/admin/retraining`)에서 쌓인 수정·새 수정·자주 틀리는 패턴·모델 버전별 점수를 볼 수 있습니다 (`evaluation/model_history.json`).
화면 위쪽에 **재학습 권장** 표시가 있습니다: 새 수정이 50건 이상이거나 같은 패턴(예: 배송 → 교환)의 새 수정이 10건 이상이면 이유와 함께 '재학습을 권장해요' (`backend/api/retraining.py`의 `RECOMMEND_PENDING`·`RECOMMEND_PATTERN`).
모델은 학습한 순서대로 '유형 분류 모델 1차·2차…'와 상태(사용 중 / 이전 모델 / 시험만)로 보이고, 아래 재학습 명령은 '개발자용'으로 접어 둡니다.

- 라벨은 `docs/labeling_guide.md` 원칙을 따랐고, 원칙이 걸린 문장은 `note`에 적었습니다 (예: "원칙 5 (누락)"). **발표 전에 사람이 한 번 훑어보는 것을 권합니다.**

- 라벨 검토 (2026-11-17): 문장만으로 회원정보 변경인지 주문 배송지 변경인지 알 수 없던 2문장을 고쳐 썼습니다
  ("주소랑 연락처 변경하고 싶어요" → "회원정보에서 주소랑 연락처 바꾸고 싶어요", "회사로 받으려고 하는데 배송지 추가는…" → "이번 주문을 회사로 받고 싶은데 배송지 바꿀 수 있나요").

## 순서

```bash
python -m backend.database.seed_demo --reset          # (필요하면) 시연 DB 새로
python -m backend.training.seed_corrections --dry-run  # 지금 모델이 틀리는 문장 보기
python -m backend.training.seed_corrections            # 틀린 문장을 시연 문의 + 분류 수정으로 저장
python -m backend.training.export_corrections          # data/corrections/category_corrections.csv
python backend/training/evaluate.py --test-file data/test/written_eval.csv --report-name category_written_eval
```

- 분류는 이 컴퓨터 안에서만 합니다 (OpenAI·LangSmith로 보내지 않음).
- `seed_corrections`는 서버의 분류 수정과 같은 코드(`backend/services/corrections.py`)로 저장하므로, 화면에서 상담원이 고친 것과 똑같이
  처리 이력·대시보드("분류 수정 n건")·내보내기에 나옵니다.

### 모델이 틀리는 곳

1. **배송 사고를 '상품'으로 봄** — 두 세트 모두에서 가장 많음 (수정 4건, 평가 2건)
   "박스는 왔는데 안에 양말 한 켤레가 빠져 있어요", "제가 시킨 건 검정인데 흰색이 왔어요", "주문한 것과 전혀 다른 상품이 왔어요"
   → 기준서 원칙 5(누락·파손·오배송은 배송)를 학습 데이터가 충분히 담지 못한 것으로 보입니다.
2. **'주문 취소'를 다른 말로 하면 '기타'** — "방금 주문한 거 그냥 없던 걸로 해 주세요", "두 개 시킨 것 중에 하나만 빼 주세요" (수정 4건)
3. **회원 정보·계정을 '기타'로 봄** — "휴대폰 번호 바뀌었는데 정보 수정 어디서 해요", "비번 재설정 메일이 안 와요"
4. **틀릴 때도 확신도가 높음** — 평가 세트에서 틀린 문장 평균 확신도 0.92 (맞힌 문장 0.93과 비슷).
   확신도 0.8 미만이면 담당자에게 넘기는 규칙으로는 이런 실수를 거르지 못합니다. 수정 데이터가 필요한 이유입니다.

## 약점 보강 문장 (LLM 생성)

수정 11건만으로는 양이 적어, **수정용 세트에서 드러난 약점 유형만** 골라 문장을 생성했습니다 (`backend/training/generate_weak.py`).
평가 세트에서만 틀린 유형(선물 포장, 페이지 표기 오류, 방송 상품 주문)은 목표에 넣지 않았고, 평가 세트 문장은 LLM에 보내지 않았습니다.

| 정답 유형 | 하위 유형 | 문장 수 | 지금 모델이 틀린 수 |
| --- | --- | --- | --- |
| 배송 | 누락 / 오배송 / 배송 중 파손 / 받는 사람·배송지 변경 / 출고 여부 | 30 / 23 / 30 / 28 / 29 | 15 / 18 / 9 / 5 / 4 |
| 주문 취소 | 바꿔 말한 취소 / 부분 취소·수량 줄이기 / 취소 후 환불 수단 | 28 / 30 / 26 | 18 / 18 / 17 |
| 쿠폰·적립금·회원 | 계정 문제 / 회원 정보 변경 | 29 / 15 | 10 / 0 |
| 상품 | 구매 전 실물 질문 (대조용) | 30 | 1 |
| | **합계** | **298** | **115** |

- 생성: gpt-5-mini, 하위 유형 11개 × 말투 3가지 × 10문장 = 330 → 걸러낸 뒤 298.
- 말투 참고: `data/supplement/seed_inquiries.csv` (직접 만든 합성 문의 128건). 라벨 5개를 기준서에 맞게 고쳤습니다 (`label_fix` 칸).
- 걸러내기: 다른 유형으로 읽히는 단어(배송 사고 문장의 교환·반품·환불 등), 단서 없음, 기존 데이터와 겹침, 평가 문장과 비슷함(글자 3개 묶음 0.5 이상).
  사람이 읽고 13문장을 뺐습니다 (받은 상품이 설명과 다름 = 상품, 사용한 적립금 복원 = 쿠폰 등; `REVIEWED_OUT`).

같은 학습 데이터(`inquiries_with_qa.csv`에서 생성 기타 문의를 뺀 26,483건 = 지금 모델과 같은 데이터), 같은 설정, seed 123.

| --- | --- | --- | --- | --- | --- |

결과 파일: `evaluation/cat_{base,corr,corr5,aug}_s123_*` (외부 테스트 보고서는 AI Hub 문장이 있어 Git 제외)

  다시 학습하니 외부 97.7%·실전 97%로 기준과 거의 같았습니다. 보고서는 두 번째 결과입니다.
  같은 seed라도 GPU 계산 차이로 결과가 이만큼 흔들릴 수 있어, 아래처럼 seed 3개 평균으로 판단했습니다.

### 약점이 고쳐졌나 (평가용 세트)

| 문장 | 정답 | 기준 | 수정만 | 수정 + 보강 |
| --- | --- | --- | --- | --- |
| 주문한 것과 전혀 다른 상품이 왔어요 | 배송 (오배송) | 상품 ✗ | ✓ | ✓ |
| 세트로 샀는데 뚜껑이 안 들어 있었어요 | 배송 (누락) | 상품 ✗ | 상품 ✗ | ✓ |
| 비번 재설정 메일이 안 와요 | 쿠폰·적립금·회원 | 기타 ✗ | 기타 ✗ | ✓ |
| 식품 유통기한 얼마나 남은 게 와요 | 상품 (원칙 6) | ✓ | ✓ | 배송 ✗ (새로 틀림) |
| 이 텐트 몇 인용이에요 | 상품 | ✓ | ✓ (5회는 ✗) | 기타 ✗ (새로 틀림) |

- **목표로 한 약점 3개는 보강 데이터를 넣었을 때만 모두 고쳐졌습니다.** 수정 11건만으로는 오배송 1개만 고쳐짐.
- 대신 **상품 질문 2개를 새로 틀렸습니다.** "~와요/오나요"가 들어간 상품 질문을 배송으로 보는 부작용으로 보입니다
  (보강 문장의 배송 사고에 "왔어요"가 많음). 다만 seed 42·7에서는 이 부작용이 나오지 않았습니다 (아래 "seed 3개로 다시 확인").
- 바뀌지 않은 오답 3개(선물 포장, 표기 오류, 방송 상품)는 일부러 보강 목표에서 뺀 유형입니다.

### 판단

- **수정 + 약점 보강이 가장 낫습니다.** 평가용 +1문장, 외부 테스트 유지(98.0%), 실전 99%(97 → 99).
- 수정만 넣으면 오배송 1개만 고쳐지고, 외부 테스트는 기준과 같은 수준입니다 (다시 학습한 값 97.7%).
  처음 학습에서 외부 96.7%로 떨어진 것은 실행할 때마다 생기는 차이였던 것으로 보입니다 (같은 설정·seed로 다시 학습하니 사라짐).
- **주의: seed 1개, 평가용 120문장이라 1문장 = 0.8%p 입니다.** 같은 데이터·seed로 다시 학습한 기준 모델도 지금 모델과
  수정용 세트에서 90.8% → 87.5%로 차이가 났습니다 (GPU 계산 차이). 서버 모델을 바꾸기 전에 seed 2개(42, 7)를 더 돌려
  평균으로 확인했습니다 (아래).

### seed 3개로 다시 확인 (2026-11-17)

seed 123의 차이가 1문장이라, 기준과 수정 + 약점 보강을 seed 42·7로 더 학습했습니다.

| 평가 | 기준 (seed 123 / 42 / 7) | 기준 평균 | 수정 + 보강 (123 / 42 / 7) | 보강 평균 |
| --- | --- | --- | --- | --- |
| 평가용 120 (주 기준) | 94.2 / 90.8 / 95.0 | 93.3% | 95.0 / 95.0 / 97.5 | **95.8%** (+2.5%p) |
| 외부 753 | 98.0 / 98.0 / 97.9 | 98.0% | 98.0 / 98.1 / 97.6 | 97.9% (같은 수준) |
| 실전 100 | 97 / 98 / 97 | 97.3% | 99 / 98 / 97 | 98.0% |
| 내부 2,650 | 97.2 / 97.3 / 97.0 | 97.2% | 97.3 / 97.5 / 96.6 | 97.1% |

- **seed 3개 모두에서 보강 쪽이 평가용 점수가 같거나 높습니다** (같은 seed끼리 비교: +0.8, +4.2, +2.5%p). 외부 테스트는 떨어지지 않았습니다.

| 목표 약점 (평가용 문장) | 기준에서 맞힌 seed | 보강에서 맞힌 seed |
| --- | --- | --- |
| 주문한 것과 전혀 다른 상품이 왔어요 (오배송) | 1 / 3 | **3 / 3** |
| 비번 재설정 메일이 안 와요 (계정) | 0 / 3 | **3 / 3** |
| 세트로 샀는데 뚜껑이 안 들어 있었어요 (누락) | 0 / 3 | **2 / 3** |

- seed 123에서 보인 부작용("유통기한 ~와요", "텐트 몇 인용"을 틀림)은 **seed 42·7에서는 나오지 않았습니다.** 한 번의 학습에서 생긴 흔들림으로 보입니다.
- 모든 모델에서 남은 오답 3개(선물 포장, 페이지 표기 오류, 방송 상품 주문)는 일부러 보강 목표에서 뺀 유형입니다.
- **결론: 수정 + 약점 보강으로 바꾸는 것이 낫습니다.** 기획서 주 기준(외부 테스트)으로는 seed 42(외부 98.1%, 평가용 95.0%, 실전 98%)가 가장 좋습니다.
- **2026-11-17 서버 모델 교체:** `category_ev_s123` → `category_aug_s42` (`models/category_classifier`, 이전 모델은 `models/category_ev_s123`에 보관). 자세한 점수는 `docs/model_card.md`.

## 2차 약점 보강 (2026-11-19, 채택 안 함)

1차 교체 모델(`category_aug_s42`)에도 남은 약점을 같은 방법으로 보강해 봤습니다. **결론: 약점은 고쳐졌지만 외부 테스트가 조금 떨어져 교체하지 않았습니다.**

### 남은 약점 (1차 모델이 수정용·1차 평가 세트에서 틀린 문장)

회원 등급("등급 올리려면 얼마나 사야 해요" → 상품), 배송 요청사항("경비실에 맡겨 달라고" → 기타), 누락("뚜껑이 안 들어 있었어요" → 상품),
기타 경계(선물 포장 → 교환, 페이지 표기 오류·라이브 방송 주문 → 상품), 결제 이상("돈은 빠져나갔는데 주문 내역이 없어요" → 기타), 단순 변심 반품 구어체("돌려보내고 싶어요" → 배송).

### 공정하게 비교하려고 한 것

- 1차 때는 평가 세트에서만 틀린 유형을 보강 목표에서 뺐습니다. 이번에는 그 유형(선물 포장·표기 오류 등)까지 목표에 넣으므로 1차 평가 세트로는 공정하게 잴 수 없습니다.
- 그래서 **보강 문장을 만들기 전에** 새 평가 세트 `data/test/written_eval2.csv`(직접 작성 120문장, 유형마다 15)를 먼저 썼습니다.
  2차 약점 문장 41개(`note`에 "2차 약점")와 헷갈리기 쉬운 대조 문장(구성 질문 "뚜껑도 같이 와요?", "유통기한 넉넉하게 오나요" 등)을 섞었고,
  기존 학습·평가·보강 데이터와 같거나 비슷한 문장(글자 3개 묶음 0.5 이상)은 바꿔 썼습니다.
- 한계: 약점을 고른 사람과 새 평가 세트를 쓴 사람이 같아, 이 점수가 오르는 것은 어느 정도 예상된 일입니다. 그래서 판단은 **외부 테스트(주 기준)** 로 했습니다.
- 1차 모델의 새 평가 세트 점수(기준값): seed 42 / 123 / 7 = 87.5 / 85.8 / 87.5%, 평균 **86.9%**

### 판단: 교체하지 않음

- 외부 테스트가 seed 3개 평균 97.9% → 97.5%로 내려갔습니다 (seed별 98.1 → 97.2, 98.0 → 97.6, 97.6 → 97.7). 미리 정한 기준 "외부 테스트가 떨어지지 않을 때만 교체"에 맞지 않습니다.
- 오른 점수(새 평가 세트 +2.8%p)는 약점을 고른 사람이 쓴 평가 세트라, 독립된 외부 테스트보다 가볍게 봤습니다.
- 실제 서비스 영향이 작습니다: 분류 확신도가 0.8 미만이면 담당자에게 넘어가고, 판단은 LLM 에이전트가 함께 합니다. 시연 시나리오에도 회원 등급·포장 문의는 없습니다.
- **배운 점:** 약점을 골라 보강하면 그 약점은 확실히 고쳐지지만, 비슷한 단어(취소·결제)를 쓰는 다른 유형에 부작용이 생기고 일반 성능과 맞바꾸게 됩니다.
  보강 데이터는 하위 유형마다 **대조 문장**(같은 단어, 다른 유형)을 함께 넣고, 독립된 테스트로 확인해야 합니다.
- 학습한 모델은 `models/category_aug2_s*`, `models/category_aug2b_s*`에 보관합니다 (Git 제외). 다시 판단할 때 바로 교체할 수 있습니다.

### 5단계: 학습 데이터 라벨 검토

**의심 문장 찾기 (OOF 예측):** seed마다 학습·평가 분할이 달라서, 각 문장을 **그 문장을 학습하지 않은 seed 모델**로 예측할 수 있습니다.
학습하지 않은 모델이 높은 확신도(0.8 이상)로 라벨과 다르게 본 문장이 라벨 오류 후보입니다.
- 대상: 기본 데이터 26,483건 중 seed 3개 중 하나라도 평가 쪽에 들어간 12,880건 (나머지는 세 seed 모두 학습에 써서 공정한 예측이 없음)
- 학습하지 않은 모델의 정확도 97.1%, 불일치 379건, 그중 확신도 0.8 이상 **252건**을 기준서(`docs/labeling_guide.md`) 원칙으로 한 건씩 검토

**검토 결과:** 252건 중 **55건만 라벨을 고침** (나머지는 라벨이 맞고 모델이 틀렸거나, 기준서로도 애매한 문장)

| 반품·환불·상품 → 교환 | 7 | "한 치수 큰 걸로 바꿀려고요" (원칙 1), "교환상품 수거는 해갔는데요" (원칙 2) |

### 판단: 현재 모델 유지

3·4·5단계 모두 미리 정한 기준을 넘지 못했습니다.
- 외부 테스트는 seed만 바꿔도 97.6~98.1%로 움직입니다(같은 데이터·설정). 다섯 가지 시도가 모두 이 범위 안에 있어, **지금 데이터로는 97.9% 근처가 한계**로 봅니다.
- 남은 오답은 문장만으로 판단하기 어려운 경계(중복 결제 → 주문 취소, 오배송 → 상품 등)가 대부분입니다. 서비스에서는 확신도가 낮으면 담당자에게 넘기고 LLM 에이전트가 함께 판단해 보완합니다.
- 더 올리려면 실제 쇼핑몰 문의를 더 모아(상담원 분류 수정 기능) 재학습하는 것이 맞습니다.
- 학습한 모델은 `models/category_aug3_s*`, `category_hp_*`, `category_fix_s*`에 보관합니다 (Git 제외).

## 상품 페이지 표기(문구) 오류 보강 (2026-11-26, 채택 안 함)

라벨 기준(`docs/labeling_guide.md` '상품 페이지 표기 문제'): 페이지의 **잘못을 알리면 기타**(직원이 사양을 확인하고 페이지를 고치는 운영 문의),
설명을 근거로 **상품을 물으면 상품**, 받은 상품이 설명과 다르면 원칙 1(교환·반품 요청이면 그 유형).

### 먼저 독립 평가 세트를 씀: `data/test/page_error_eval.csv` (30문장, 직접 작성)

표기 오류 15(→ 기타) · 대조 10(설명을 근거로 한 사양·구매 전 질문 → 상품) · 원칙 1 5(받은 상품이 설명과 다름 → 교환·반품·배송).
기존 평가 세트에는 표기·설명 관련 문장이 2~7개뿐이라 이 경계를 잴 수 없었습니다. 학습 문장과 다른 사람(방식)이 쓴 문장입니다.

지금 모델(`category_aug_s42`): **표기 오류 6/15**, 대조 9/10, 원칙 1 5/5. 표기 오류를 상품으로 보면서 확신도가 0.93이라 0.8 안전장치도 거르지 못함.

### 학습: 2차 보강 문장 중 두 하위 유형만 (`data/supplement/page_error_boost.csv`, 41문장 × 2번)

2차 보강(위)이 실패한 원인은 '결제 이상' 하위 유형이었으므로, 이미 사람이 검토한 **페이지 표기 오류 14(기타) + 구성·사양 질문 27(상품, 대조)** 만 골라
1차 보강 데이터에 더했습니다 (`train.py --extra-train … page_error_boost.csv --extra-repeat 1 1 2`, 모델 `models/category_page_s*`).

| 평가 (seed 42/123/7 평균) | 지금 (`category_aug`) | 표기 오류 보강 |
| --- | --- | --- |
| **외부 테스트 753** (주 기준) | 97.92% | 98.10% (+0.18%p) |
| 실전 100 | **98.0%** | 96.67% (−1.33%p) |
| 직접 쓴 평가 120 | 95.83% | 96.39% |
| 직접 쓴 평가2 120 | 86.94% | 86.11% |
| **경계 평가 30** | 65.6% | 72.2% (+6.7%p) |
| 내부 2,648 | 97.14% | 97.13% |

- **부작용이 바로 그 경계에서 남**: 실전의 "상세페이지 색상이랑 실제 색상이 많이 다른가요?"(구매 전 질문 = 상품)를 seed 2개가 기타로 봄.
  모델이 '의도(알림 vs 질문)'가 아니라 '상세페이지 + 다르다 = 기타'라는 겉모양을 배움.
- **고쳐진 것도 적음**: 표기 오류 15개 중 7~10개는 여전히 상품 (상품명 ↔ 사진 색, 원산지, 설명끼리 다름, 이미지 깨짐, 단위).
- **판단: 교체하지 않음.** 외부 테스트 기준은 통과했지만 실전이 떨어졌고, 고치려던 경계에서 반대 방향 오답이 생김. 모델은 `models/category_page_s*`에 보관.
- **배운 점**: 이 경계는 단어가 아니라 **의도**로 갈림. 14문장으로는 부족하고, 같은 단어를 쓰는 **짝 문장**(아래 '분류 기준을 더 분명하게')이 필요함.

### 분류 기준을 더 분명하게 하려면

1. **라벨 결정 질문 하나로 고정**: "고객이 쇼핑몰에 **고쳐 달라고 알리는가**(기타) / **상품에 대해 묻는가**(상품) / **받은 물건을 어떻게 해 달라는가**(원칙 1)".
   애매하면 마지막 문장의 동사(달라요·틀려요·수정해 주세요 vs 되나요·인가요 vs 교환·환불해 주세요)를 봄.
2. **짝 문장으로 데이터 만들기**: 같은 단어를 쓰는 문장 두 개를 한 쌍으로 ("상세페이지 색이 실물이랑 많이 다른가요?" = 상품 /
   "상품명은 그레이인데 상세 사진은 베이지예요, 어느 게 맞나요?" = 기타). 하위 유형마다 30쌍 이상, 사람이 검토.
3. **두 사람이 따로 라벨을 달아 일치율 확인**: 일치하지 않는 문장이 곧 기준이 모호한 곳이므로 기준서 예시로 추가.
4. **모델 대신 판단 단계에서 보완**: 분류가 상품이어도 "두 곳의 표기가 다르다"는 신호(A엔 … B엔 …, 표기·적혀·나와 + 달라·틀려·잘못)가 있으면
   LLM이 유형을 다시 보거나 상담원에게 넘기게 함. 데이터를 더 모으기 전까지 가장 적은 위험으로 고칠 수 있는 방법.
5. **상담원 수정을 계속 모음**: 문의 상세에서 상담원이 고친 분류가 재학습 데이터(`data/corrections`)가 되므로, 실제 문의로 쌓인 짝 문장이 가장 좋은 데이터.
6. **경계 평가 세트(`page_error_eval.csv`)를 회귀 테스트로 유지**: 모델을 바꿀 때마다 이 30문장을 같이 잼.

### 2차 시도: 짝 문장 (`--round 4`, 2026-11-26, 채택 안 함)

주제 6개(색상·사진, 용량·크기·단위, 가격 표시, 원산지·소재·성분, 설명끼리 다름, 페이지 깨짐·다른 상품 설명)마다
'표기 오류를 알림(기타)'과 '같은 주제의 상품 질문(상품)'을 짝으로 생성 (`generate_weak.py --round 4`, gpt-5-mini, 직접 만든 합성 문의만 말투 참고로 전송).
252 → 자동 걸러내기 158 → 사람이 전부 읽고 5문장 제외(`REVIEWED_OUT`) → **153문장** (`data/supplement/generated_weak4.csv`, 기타 64 · 상품 89).
41문장(위)과 함께 1번씩 넣어 seed 3개 학습 (`models/category_pair_s*`).

| 평가 (seed 3개 평균) | 지금 | 41문장 | 짝 문장 |
| --- | --- | --- | --- |
| **외부 테스트 753** | **97.92%** | 98.10% | 97.61% (−0.31%p) |
| 실전 100 | **98.0%** | 96.67% | 96.33% (seed 123만 93%) |

- 경계는 가장 많이 좋아졌지만(표기 오류 남은 오답 9 → 5~6), **외부 테스트가 떨어져 교체 기준에 맞지 않음**.

- **다음 시도**: 보강 데이터의 상품 : 기타를 1 : 1 이하로 맞추고(상품 짝 질문 일부만), 표기 오류 문장을 더 다양하게(품절·배송 예정일·이미지 깨짐 등
  경계 평가에서 계속 틀리는 주제). 교체 판단은 같은 기준(외부 테스트 3개 평균이 떨어지지 않음 + 실전·경계 평가 확인).
